## 一、決定性證據：原版已經實作了，而且比提案更嚴謹

### 1.1 原版 `/backtest/` 頁面就是「回推驗證」

`src/app/backtest/page.tsx`（逐字複刻自實站 `capture`）的原文：

> 「輸入一檔股票，系統找出最常操作它的券商分點，然後把『跟著這個分點做』這件事套回過去半年**一筆一筆算一次**，看歷史上會是什麼結果。」
>
> 「如果過去半年，每次某個分點大買這檔股票你就跟著做，最後會賺還是賠？系統把規則**套回歷史資料，一筆一筆列出來**，並**算進手續費與交易稅**。」

實際呈現的統計卡（2330 台積電／元大分點，29 筆樣本）：

| 指標 | 值 |
|---|---|
| 歷史樣本符合率 | **45%** |
| 平均每筆 | +0.14% |
| 累積報酬 | +2.28% |
| 交易筆數 | 29 |

> **注意這組數字的教學意義**：符合率只有 45%（低於一半），但累積報酬是 **+2.28%**。
> 這正是原版要教的事——**勝率低不等於賠錢**，因為賺賠比不同。只看勝率會誤判。

### 1.2 原版明文寫出的三條護欄（在 `/backtest/` 的「怎麼看」與「什麼時候別用它」）

> **「先看樣本筆數：少於 20 筆的統計基本上沒有意義，運氣成分太大。再看符合率和累積報酬，兩個要一起看——符合率高但累積是負的，代表贏的時候賺一點、輸的時候賠很多。」**

> **「最重要的一件事：這是『過去發生過的事』，分點的操作習慣會變，人員異動、資金規模改變都會讓歷史失效，所以歷史好不代表接下來也好。另外它是用收盤價模擬的，實際上你不一定買得到那個價。」**

> 頁尾註記：「已扣手續費 1 折、證交稅與滑價約 **0.39%**（留倉來回）」

### 1.3 原版 `/manual/` 第 06 章的「分點操盤驗證」三條規則

> 1. 查看特定主力玩法過去的**樣本數、歷史樣本符合率與報酬分布**。
> 2. **樣本少於 5 次時參考價值很低**。歷史樣本符合率高也要**核對平均損益與交易成本**。
> 3. **歷史回測會失效，應比較不同市場環境，不能把單一期間當保證**。

### 1.4 最關鍵：原版刻意不做「機率／方向」輸出

`/methodology/` 頁面（演算法權威來源）原文：

> **研究熱度分數（BlackScore）**——衡量「這檔股票最近的資料值不值得花時間研究」的 0–100 分，**不是買賣訊號、不是漲跌預測**。
> - 分項：分點資金（25）、買方集中（15）、法人動向（20）、技術結構（15）、量能動能（15）、波動風險（10）
> - 每個分項都是**一句已發生的客觀事實**（例：投信連 4 日買超），逐項加分**可追溯**

> **資金雷達（Black Radar）**——全部為盤後統計與歷史事實排序，**不含方向研判**

`/manual/` 第 06 章：

> 「**條件整理**」模式：把主觀假設拆成**可驗證欄位、資料日、目前值與作廢條件**；**不提供未來方向、機率或平台價位**。
>
> 「**新聞解讀**」模式：整理消息敘事、影響對象與新舊程度，只引用站內實際新聞，**不外推股價方向**。

> **AI 用來整理、解釋與檢討，不代替你承擔風險，也不應製造不存在的數據。**

個股頁：

> 一般會員版**不提供 5 分 K 盤中判讀、方向或平台進出指令，也不預測下一根 K 棒**。

### 1.5 這對照出一個嚴重問題

原版博主**有授權資料**（分點、法人、資券、集保）、**有 453 檔個股頁**、**有完整方法論**——他**仍然**只敢說「這是統計，不是預測」，並在每一處標示「非投資建議」。

而 GOD 辦公室目前在做什麼？`backtest_20260924.json` 裡填著 `sample: 312`、`win_rate: 54.2%`——**正是原版刻意避免的那種「機率宣稱」，而且那個數字是 LLM 自己填的、沒有任何引擎算過。**

> **一句話**：原版有能力做卻選擇不做的事，我們資料更少卻做了，還做了假的。

## 二、您想法中「可行的那一半」與「危險的那一半」

### ✅ 可行的那一半：建立事件帳本（Event Ledger）

把每個交易日的「已發生事實」結構化記錄下來，累積成可查詢的統計表。這完全可行，而且是地基。

### ⚠️ 危險的那一半：直接拿歸因結果去「推估漲跌因素」

這裡有一個**致命的方法論陷阱，原版沒有明講，但必須點出來**：

> **選擇偏差（Selection Bias）**
>
> 如果只挑「今天漲 5% 的股票」去回推，你找到的**所有**「依據」都無法證明有預測力。
> 因為你沒有看「**有同樣依據、但沒漲**」的股票。

**具體例子**：

假設台積電今天漲 5%，你回推發現「法人買超」「量增」「有新聞」。於是你說「法人買超是漲的原因」。

但如果全市場 90% 的股票當天都有法人買超呢？那「法人買超」就完全沒有解釋力——它是**背景雜訊**，不是**原因**。

**沒有對照組，就無法區分「有這個特徵」與「有這個特徵就會漲」。**

## 三、必須補上的三個方法論要件

您的想法要能成立，必須加上這三件事（前兩項是原版有暗示但沒明講的）：

### 要件 1：對照組（Control Group）

```
事件組：發生「法人買超 > 1000 張」的股票，T+3 平均報酬 = +0.8%
對照組：同期間全市場平均報酬              = +0.3%
────────────────────────────────────────────────
超額報酬 = +0.5%   →  這個事件「可能有」解釋力

若超額報酬 ≈ 0     →  這個事件沒有解釋力，只是背景雜訊
```

**只報事件組報酬，不報對照組，就是自欺。**

### 要件 2：時間切分（避免 look-ahead bias）

這是財經機器學習最常見的**致命錯誤**：

> **用「今天的收盤資料」解釋「今天的漲」——但收盤資料是漲完才有的。**

正確做法：**只能用 T-1 收盤為止可得的資料，去解釋 T 日的結果。**

例：
- ✅ 「T-1 日法人買超 1000 張 → T 日上漲的機率」
- ❌ 「T 日法人買超 1000 張 → T 日上漲的機率」（同一天的資料，漲完才知道，沒有預測價值）

### 要件 3：樣本數與基準率（原版已明文）

- 樣本 < 20 筆：**不宣稱任何勝率**（原版 `backtest` 頁標準）
- 樣本 < 5 次：**參考價值很低**（原版 `manual` 標準）
- 必須同時報告：**樣本數、符合率、平均損益、累積報酬、交易成本**
- 必須對比**基準率**（同期大盤報酬），否則無法判斷是「策略有效」還是「剛好處在多頭」

## 四、落地設計：事件帳本 + 事件研究法

這套方法在財經學術界叫**事件研究法（Event Study）**，已成熟使用數十年，可直接照抄。

### 第一層：事件帳本 `event_ledger`（只記事實，不記推論）

每個交易日收盤後，對每檔股票記錄：

| 欄位 | 說明 | 現況 |
|---|---|---|
| `symbol` / `industry` | 標的與產業 | ✅ 有 |
| `trade_date` | 交易日 | ✅ 有 |
| `event_type` | `chip` / `news` / `technical` / `market` | ⚠️ 部分 |
| `event_code` | 例如 `INST_BUY_1000`（法人買超>1000張） | 需定義 |
| `event_value` | 事件強度（張數、金額、分數） | 需計算 |
| `market_ctx` | 加權／櫃買／夜盤／美股／VIX | ❌ 缺 |
| `outcome_t1` / `t3` / `t5` | T+1/T+3/T+5 實際報酬 | 需回填 |
| `benchmark_t1` / `t3` / `t5` | 同期大盤報酬（對照） | 需計算 |

### 第二層：條件機率查詢（含對照）

```sql
-- 對每個事件，算「超額報酬」而非絕對報酬
SELECT event_code,
       COUNT(*)                                        AS 樣本數,
       AVG(outcome_t3)                                 AS 事件組報酬,
       AVG(benchmark_t3)                               AS 對照組報酬,
       AVG(outcome_t3) - AVG(benchmark_t3)             AS 超額報酬,
       SUM(CASE WHEN outcome_t3 > 0 THEN 1 END)*1.0/COUNT(*) AS 符合率
FROM event_ledger
WHERE trade_date < :as_of          -- 時間切分，避免 look-ahead
GROUP BY event_code
HAVING COUNT(*) >= 20              -- 樣本門檻
```

**只有「超額報酬顯著為正且樣本 ≥ 20」的事件，才能進入下一步。**

### 第三層：歸因（您說的「回推」）

對某次大漲，列出當日所有事件，**標記哪些是歷史上有超額報酬的**：

```
2330 台積電 2026-09-28 漲 +5.2%
├─ 法人買超 12,340 張     → 歷史超額報酬 +0.5%（n=412）  ← 有解釋力
├─ 量比 2.3 倍            → 歷史超額報酬 +0.1%（n=1,203） ← 弱
├─ 新聞：法說會上調展望   → 無歷史樣本                     ← 無法驗證
└─ 分點集中度 8%          → 資料未入庫                     ← 誠實標示

⚠️ 這是「事後解釋」，不是「事前預測」
```

## 六、與前次路線圖的關係

這個提案正好補上上一輪診斷出的**最致命缺口**（閉環驗證缺失）：

| 上一輪建議 | 本提案對應 |
|---|---|
| `prediction_ledger`（預測落帳 → T+1/T+3/T+5 回填） | **同一個機制**，本提案補上了「歸因層」 |
| `event_ledger`（事件機率表） | 本提案的第四節設計 |
| 喚醒 `calibrationEngine` | 該引擎的 `calibrateSignalScore` / `evaluateParameters` **就是為此而生** |

**兩者合併後，形成完整閉環：**

```
事實記錄（event_ledger）
   → 事前預測落帳（prediction_ledger）
   → 事後回填實際結果
   → 計算超額報酬（含對照組）
   → 校準條件權重
   → 回饋到選股條件
```

## 七、建議

1. **採納您的想法**，但以「事件研究法」的標準形式落地（對照組 + 時間切分 + 樣本門檻）

4. ❌ **不要**讓 LLM 自己填勝率數字（目前 `backtest_20260924.json` 的問題）
